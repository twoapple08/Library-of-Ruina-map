# 자유 형체 기반 사용법 (2026-10-12 만듦)

모든 공간을 모드 요소로 다시 만들 때 쓰는 공용 기반. 코드: `tools/forms.py`(형체·투영·칸 배정·주입), `tools/form_textures.py`(텍스처),
Java `mod/src/main/java/ruina/library/form/`(블록) · `client/form/`(그리기). 임시 시험대는 이미 삭제했다.
실제 입체 부품은 `builders/detail.py`, 적용 예는 `builders/exterior.py`와 `builders/exterior_surroundings.py`.

## 구조 한눈에
| 요소 | 만드는 곳 (Python) | 게임에서 |
|---|---|---|
| 자유 형체 (정적) | `b.form(공간).add(Quads)` | `ruina:form` 블록이 칸마다 자기 조각을 청크 메시에 구움 (매 프레임 비용 없음, Sodium·Iris·BSL 그대로) |
| 충돌 | `lay.solid(...)`·`lay.solid_box(...)` → `minecraft:barrier` | 보이는 모습은 형체, 걷는 건 barrier → 주입 때 `ruina:form[solid=true]` |
| 빛 | 빈 칸에 `minecraft:light[level=N]` | 그 칸에 형체가 있으면 `ruina:form[light=N]` (같은 밝기) |
| BSL 발광 | 재질 `glow=색 번호` (`config.SHADER_GLOW_COLORS`, 약한 빛 +25) | `ruina:form[glow=N]` → block.properties block.150XX |
| 원화 투영 | `F.project_scene(parts, Camera, 원화재질)` | 도착 시점에서 원화와 같음, 걸으면 입체 |
| 움직임 | `lay.mover(F.Mover(pos, mesh, pivot, motion, axis, period, amp))` | `ruina:mover` 블록 엔티티 렌더러: spin·swing·bob·still·**follow**(카메라를 따라오는 먼 배경) |
| 날리는 종이 | `lay.emitter(F.Emitter(box, rate, sprites, wind, ...))` | 플레이어 64칸 안 상자에서만 파티클 |

빌드 흐름: 빌더 → `build_all` 끝 `b.forms.finalize()`(면을 1칸 이하로 나눠 중심 칸에 배정, 칸이 보이는 블록이면 법선 쪽 빈 칸으로 옮김)
→ 바닐라 서버 검증·조명 → `forms.inject`(저장된 리전에서 자리 표시 → 형체 블록, 움직임 블록 엔티티) → `mod_pack` 이 `assets/ruina/forms/`·텍스처를 씀.
월드 캐시 지문에 `tools/forms.py` 등이 들어감 (바꾸면 건축물 새로 빌드).

## 형체 만들기 (tools/forms.py)
- 면 묶음 `Quads`: P(n,4,3) UV(타일 단위) C(RGBA 배수) N(법선) M(재질). 앞면 = 바깥에서 반시계. 뒷면은 안 그림 → 얇은 것은 `two_sided`
- 도형: `plane` `box` `sweep`(곡선 따라 단면: 가지·관, profile·twist·squash) `revolve`(회전체: 탑·기둥·돔, arc) `heightfield` `ribbon`(띠, 양면)
  `ellipsoid` `grid`(직접 격자). 변형: `.translate` `.rotate(axis, 도, origin)` `.scale` `.flipped()` `.tint` `.color_by` `bake_light` `gradient_y`
- UV 는 한 면이 타일(텍스처 한 장) 경계를 넘으면 안 됨 → 도형 함수가 맞춰 줌 (`fit_tiles`). 직접 `grid` 쓸 때 주의
- 재질 `F.mat(이름, 스프라이트, layer=solid|cutout|translucent, emissive, ao, flat, glow)`
  - 걸어 다니는 가까운 것: 기본(조명·AO 받음) → 입체감 / 원화 투영·빛: `emissive=True, flat=True, ao=False` → 원화 색 그대로
- 텍스처: `form_textures.bark/planks/paper/book_spines/stone_slab/metal/glow/flat/art(원화)` (16의 배수 크기). 스프라이트 이름 `ruina:block/form/<이름>`.
  바닐라 스프라이트도 됨 (`minecraft:block/stone`)
- 카메라 `F.Camera(눈 위치, yaw, pitch, fov=70(세로), 16/9)` — 마인크래프트와 같은 각도. `Camera.look_at`. `cam.mc()` = tp 명령
- 미리보기(게임 없이): `F.render_preview([면들], cam, W, H)` → PIL 이미지 (원화와 나란히 붙여 비교)

## 검증용 면 채움 미리보기 (2026-10-16)

- `python -u -m tools.form_preview exterior previews/exterior_detail_compare.png` (다른 공간도 같은 형식).
- `tools/form_raster.py`/`.c`: 삼각형·깊이·원근 UV·뒷면·cutout 검사. mover는 t=0 스냅샷을 포함.
  큰 면을 점으로 찍던 옛 미리보기의 빈 픽셀을 제거했다. 네이티브 C 컴파일러 `cc`가 필요하며 결과는 /tmp 캐시.
  이 의존성은 **오프라인 도구 전용**, 배포 모드/월드에는 들어가지 않는다.
- 한국어 캡션 폰트는 `RUINA_PREVIEW_FONT` 또는 시스템 Noto Sans CJK를 사용한다.
- 검은 면과 빈 픽셀은 깊이로 구분. 반투명·파티클·게임 조명·FPS 검증은 실제 게임에서 한다.
- 원화 투영 자체의 Z버퍼는 기존 forms.py 구현을 유지한다. 미리보기가 좋아졌다는 이유로
  원화 일치/모델링 완성을 가정하지 않는다. 뒤·옆·위·근접 화면을 별도로 확인한다.

## 주의
- 면 하나는 자기 칸 밖으로 32블록 넘게 못 뻗음 (칸 배정 전 1칸 이하로 나누므로 실제로는 1칸 남짓)
- 형체 칸 = 공기·barrier·light 칸만. 보이는 바닐라 블록 칸에 걸린 면은 옆 빈 칸으로 옮김 (`finalize` 결과 '옮김'·'버림' 확인)
- 움직이는 형체 자리는 빈 칸 (겹치면 가까운 빈 칸으로 자동 이동). follow 는 그 블록이 불러와진 동안만 그림 (렌더 거리 안)
- 원화 텍스처는 1024×576 (아틀라스 크기·밉맵 고려). 한 공간에 원화 여러 장이면 잘라서 필요한 부분만
- 성능(GTX1050ti): 형체는 정적 메시라 면 수만 중요. 먼 곳은 굵게(면 크게), 가까운 곳만 촘촘히. 움직이는 형체는 수백 개 이하
